이 매뉴얼은 세 부분으로 되어 있습니다.

  • 1부 작업자: 매일 검사를 돌리는 사람. RUN 탭만 사용합니다.
  • 2부 엔지니어: 카메라, 레시피, 설정을 맞추는 사람. 모든 탭을 사용합니다.
  • 3부 문제 해결: 화면·로그 메시지별 조치.

그림은 [그림 x-x] 자리에 나중에 넣습니다.

1부. 작업자

1. 화면 보는 법

그림 1-1: 프로그램 전체 화면 (RUN 탭)그림 준비 중

1-3. 판정의 뜻

판정뜻
OK기준에 맞음
NG기준에 맞지 않음, 또는 제품을 찾지 못함
ERROR검사를 끝까지 하지 못함 (카메라 취득 실패, 레시피 오류 등). 개수는 NG 로 셉니다.

NG 와 ERROR 일 때 결과 표의 측정값이 비어 있으면, 앞 단계(제품 찾기 등)에서 실패해서 값을 믿을 수 없다는 뜻입니다.

2. 작업 시작

  1. 같은 PC 에서 QuickBuild 나 다른 검사 프로그램이 켜져 있으면 먼저 종료합니다. (같은 카메라를 두 프로그램이 함께 쓰면 연결이 끊어집니다.)
  2. VProSTD 를 실행합니다. 프로그램이 스스로
    • 마지막에 쓰던 레시피를 불러오고,
    • 저장된 카메라에 연결합니다.
  3. 위쪽에서 확인합니다.
    • Recipe 이름이 오늘 검사할 제품인지
    • Camera 표시등이 초록인지
  4. 카메라 연결에 실패하면 경고 창이 뜹니다. 카메라 전원·케이블을 확인하고 프로그램을 다시 실행합니다. 그래도 안 되면 엔지니어에게 알립니다.
  5. 필요하면 COUNT RESET 으로 개수를 0 으로 합니다.
  6. 기준 제품으로 RUN ONCE 를 눌러 OK 가 나오는지 봅니다.
  7. AUTO RUN 을 누릅니다.

3. 작업 중

  • 판정 칸, 개수, YIELD 를 봅니다.
  • 멈출 때는 STOP 을 누릅니다.
  • AUTO RUN 중에는 다른 탭으로 갈 수 없고, 레시피를 바꾸거나 종료할 수 없습니다. 먼저 STOP 을 누릅니다.
  • AUTO RUN 이 스스로 멈추면 로그에 AUTO RUN 정지: <이유> 가 주황색으로 남습니다. 이유를 확인하고 3부를 봅니다.

4. 제품(레시피) 바꾸기

  1. STOP 을 누릅니다.
  2. Load Recipe 를 누르고, 목록에서 제품 레시피를 고릅니다.
  3. 위쪽 Recipe 이름이 바뀌었는지 확인합니다. (카메라 노출은 레시피 값으로 자동으로 바뀝니다.)
  4. 기준 제품으로 RUN ONCE → OK 확인 → AUTO RUN.

5. 작업 끝

  1. STOP 을 누릅니다.
  2. EXIT 를 누르고 확인 창에서 예 를 누릅니다. 카메라는 종료할 때 자동으로 해제됩니다.

6. 이상할 때

상황작업자가 할 일
ERROR 가 계속 나옴, AUTO RUN 이 스스로 멈춤STOP → 엔지니어에게 알림
기준 제품인데 NG 가 계속 나옴STOP → 엔지니어에게 알림
Camera 표시등이 회색프로그램 종료 → 카메라 전원·케이블 확인 → 다시 실행. 안 되면 엔지니어에게 알림
경고·오류 창이 뜸창의 문구를 사진으로 찍거나 적어 두고 엔지니어에게 알림

엔지니어에게 알릴 때는 다음을 함께 알려 주세요.

  • 일어난 시간
  • 화면 맨 아래 상태 줄 문구 (또는 로그 창의 빨강·주황 줄)
  • 판정 (NG / ERROR)과 레시피 이름

작업자가 하지 않는 것: RECIPE 탭·SYSTEM 탭·CONNECT CAMERA 탭의 값 변경, SAVE, SAVE CAMERA, DELETE.

작업자 모드에서 이 탭을 누르면 엔지니어 비밀번호 창이 뜹니다. 작업자는 CANCEL 을 누릅니다.

2부. 엔지니어

엔지니어 모드

  • 프로그램은 항상 작업자 모드로 시작합니다. 작업자 모드에서는 RUN 탭만 열립니다.
  • RECIPE / CONNECT CAMERA / SYSTEM 탭을 누르거나 EXIT 왼쪽 작업자 모드 버튼을 누르면 비밀번호 창이 뜹니다. 맞게 입력하면 엔지니어 모드가 됩니다 (버튼이 주황색 엔지니어 모드 로 바뀜).
  • 작업이 끝나면 엔지니어 모드 버튼을 눌러 작업자 모드로 돌아갑니다 (RUN 탭으로 이동).
  • 모드가 바뀔 때마다 로그에 SYSTEM: 엔지니어 모드 / SYSTEM: 작업자 모드 가 남습니다. 비밀번호가 틀리면 SYSTEM: 엔지니어 비밀번호 틀림 (주황).

비밀번호

  • 처음 정하기: 비밀번호가 아직 없으면 처음 엔지니어 탭을 누를 때 "엔지니어 비밀번호 정하기" 창이 뜹니다. 새 비밀번호를 두 번 입력합니다 (4자 이상). 장비 PC 마다 처음 한 번 정합니다.
  • 비밀번호는 실행 파일 옆 system.xml 에 비밀번호 글자가 아니라 계산한 값(EngineerPasswordSalt, EngineerPasswordHash)으로 저장됩니다.
  • 잊었을 때: 프로그램을 끄고 system.xml 의 <EngineerPasswordSalt>, <EngineerPasswordHash> 값을 비운 뒤 다시 실행하면 처음 정하기 창이 다시 뜹니다.
  • 비밀번호 변경 버튼은 아직 없습니다 (추가 예정). 바꾸려면 위의 '잊었을 때' 방법으로 지우고 다시 정합니다.
  • 이 기능은 작업자의 실수를 막는 용도입니다. system.xml 을 고칠 수 있는 사람까지 막지는 못합니다.

7. 첫 설정 (SYSTEM 탭)

그림 7-1: SYSTEM 탭그림 준비 중
항목내용
Pixel X / Pixel Ymm/pixel. 레시피 ToolBlock 에 PixelX, PixelY 입력이 있으면 이 값이 들어갑니다. 숫자만 입력 (예: 0.0125)
Base Path기본 폴더. 아래 경로를 비워 두면 Base Path 아래 System, Recipe, Log, Result 로 정해집니다. 비워 두면 실행 파일 옆 Data
System Path설정 파일 사본을 두는 폴더 (SAVE / LOAD 창이 여기서 열림)
Recipe Path레시피 폴더. RECIPE 탭 목록과 Load Recipe 가 이 폴더를 씁니다
Log Path로그와 결과 CSV
Result Path검사 이미지 저장 폴더
Save Image TypeBMP / JPG
Origin Save원본 이미지 저장

  • SAVE: 저장 창에서 파일을 고르면 그 파일과 실행 파일 옆 system.xml 에 함께 저장되고 바로 적용됩니다.
  • LOAD: 고른 설정 파일을 화면에만 읽어 옵니다. 적용하려면 SAVE 를 눌러야 합니다.
  • 프로그램이 실제로 쓰는 설정은 항상 실행 파일 옆 system.xml 입니다.

8. 카메라 (CONNECT CAMERA 탭)

그림 8-1: CONNECT CAMERA 탭그림 준비 중

카메라는 레시피와 따로 관리합니다. 연결할 카메라는 system.xml 에 저장되고, 프로그램을 시작하면 저장된 카메라에 자동으로 연결합니다.

8-1. 처음 연결하거나 카메라를 바꿀 때

  1. QuickBuild 등 카메라를 쓰는 다른 프로그램을 종료합니다.
  2. SEARCH: 연결된 카메라를 찾아 목록에 넣습니다 (확인 창에서 예).
  3. 목록에서 카메라를 고르고 CONNECT (확인 창에서 예).
  4. TRIGGER 로 1장 찍어 이미지를 확인합니다. 또는 LIVE 로 계속 보면서 초점·조명을 맞춥니다.
  5. 노출 (ms) 을 맞춥니다. 바꾸는 즉시 카메라에 적용됩니다.
  6. SAVE CAMERA: 지금 카메라(시리얼, 영상 형식)를 system.xml 에, 노출을 현재 레시피에 저장합니다.
    이후 프로그램을 시작하면 이 카메라에 자동으로 연결됩니다.

8-2. 버튼 정리

버튼하는 일
SEARCH연결된 카메라 찾기. 저장된 카메라가 있으면 그것을 골라 둠
CONNECT목록에서 고른 카메라 → 없으면 저장된 카메라 → 없으면 첫 번째 카메라에 연결. 연결되면 현재 레시피 노출 적용
TRIGGER1장 취득해서 보여 줌 (검사 안 함). 이 이미지는 레시피 입력에도 들어가 RECIPE 탭에서 바로 실행해 볼 수 있음
LIVE한 번 누르면 ON, 다시 누르면 OFF. ON 중에는 TRIGGER 가 막히고, 다른 탭으로 가면 자동으로 OFF
노출 (ms)레시피별 값. 연결 전에는 레시피에 저장된 값(없으면 빈칸)을 보여 줌
SAVE CAMERA카메라 → system.xml, 노출 → 현재 레시피 설정 파일

8-3. 자동 연결

  • 시작할 때 저장된 카메라가 있으면 확인 창 없이 연결합니다. 로그: CAMERA: 저장된 카메라에 자동 연결.
  • 저장된 카메라가 없으면 연결하지 않고 주황색 로그를 남깁니다. 8-1 대로 연결하고 SAVE CAMERA 를 누르세요.
  • 연결에 실패하면 경고 창과 빨강 로그 CAMERA: 자동 연결 실패 - ... 가 남습니다.
  • 자동 연결을 끄려면 실행 파일 옆 system.xml 의 <Camera> 안 <AutoConnect> 를 false 로 바꿉니다 (화면에는 이 설정이 없음).

8-4. 종료와 카메라 해제

  • 종료하면 카메라를 해제하고 로그에 CAMERA: 해제 완료 (n 대) 를 남깁니다.
  • 카메라는 이 프로그램을 종료해야 해제됩니다. 같은 카메라를 다른 프로그램에서 쓰려면 VProSTD 를 먼저 종료합니다.

9. 레시피 (RECIPE 탭)

그림 9-1: RECIPE 탭 (왼쪽 편집 화면, 오른쪽 레시피 목록)그림 준비 중

레시피 = Recipe Path 안의 <이름>.vpp (검사 ToolBlock) + <이름>.recipe.xml (노출, File Mode 등 레시피 설정).

버튼하는 일
LOAD목록에서 고른 레시피를 불러옴
COPY고른 레시피를 새 이름으로 복사 (.vpp 와 설정 파일)
NEW빈 레시피를 만듦 (Inputs InputImage, Outputs Result 포함). 만든 뒤 바로 불러올지 물어봄
SAVE저장 창에서 이름을 고름. 지금 레시피 이름 = 덮어쓰기, 다른 이름 = 다른 이름으로 저장 후 그 레시피로 바뀜. Recipe Path 밖에는 저장하지 않음
DELETE고른 레시피의 .vpp, .vpp.bak, .recipe.xml 삭제 (되돌릴 수 없음). 지금 불러온 레시피는 삭제할 수 없음
  • SAVE 할 때마다 이전 파일이 .vpp.bak 으로 1개 남습니다. 저장 중 오류가 나도 원본은 바뀌지 않습니다.
  • SAVE 는 툴의 마지막 이미지·결과를 빼고(Minimum) 저장합니다. 학습한 패턴은 남습니다. 그래서 레시피를 막 불러왔을 때는 편집 화면에 이전 결과 그래픽이 없고, 한 번 실행하면 보입니다.
  • 편집 화면 툴바의 열기·저장 버튼은 일부러 숨겼습니다. 저장은 항상 오른쪽 SAVE 로 합니다.
  • 레시피를 불러올 때 필수 항목이 없으면 경고 창이 뜹니다 (10장).
  • 레시피를 불러올 때 .vpp 안에 카메라(AcqFifo)·I/O 설정이 있으면 경고 창이 뜹니다. QuickBuild 에서 지우고 다시 저장하세요.

9-1. 편집 화면에서 바로 실행해 보기

  1. CONNECT CAMERA 탭에서 TRIGGER 를 누르거나, File Mode 에서 Single Image / Image Folder 를 고릅니다. 그 이미지가 레시피 입력에 들어갑니다.
  2. RECIPE 탭 편집 화면에서 실행 버튼을 누르면 그 이미지로 실행됩니다.
  3. 고친 뒤에는 오른쪽 SAVE 를 누릅니다. 저장하지 않고 종료하면 변경이 사라집니다.

9-2. File Mode 와 레시피

File Mode 켜짐/꺼짐 상태는 레시피마다 저장됩니다. File Mode 를 켠 채로 레시피를 저장하면, 다음에 그 레시피를 불러올 때 File Mode 로 시작합니다.

생산용 레시피는 File Mode 를 끄고 저장하세요. (결과 표·로그의 출처가 CAMERA 인지로 확인)

10. 레시피(Job) 작성 규칙

원본: VProSTD/README.md 2-1. 아래는 2026-11-20 기준으로 옮긴 것입니다.

그림 10-1: 규칙에 맞는 ToolBlock 구조 예 (Inputs, Locate, LEFTside, RIGHTside, CogResultsAnalysisTool)그림 준비 중

필수

  1. 이미지 입력: Inputs 에 이름이 정확히 InputImage 인 입력 (형식 ICogImage 또는 CogImage8Grey, 대소문자까지 같게). 다른 이름이면 바꿉니다. 흑백 입력에 컬러 이미지가 오면 자동으로 흑백으로 바꿔 넣습니다.
  2. 판정: 최상위 ToolBlock 바로 안에 CogResultsAnalysisTool. 판정 Accept = OK, Error = ERROR, 나머지 = NG.
    • 판정 툴이 여러 개이면 <이름>.recipe.xml 의 ResultsAnalysisToolName 에 쓸 툴 이름을 적습니다.
    • 판정 툴이 없으면 Outputs Result (bool, true = OK) 로 판정합니다 (NEW 로 만든 기본 레시피).
    • 판정 툴 앞의 툴이 Reject/Error 이면 판정 툴이 Accept 여도 NG 로 하고, 결과 표 값은 비웁니다.
  3. 카메라·I/O 를 넣지 않습니다. 카메라는 CONNECT CAMERA 탭에서 연결합니다.

선택

  1. Inputs PixelX, PixelY (double): 있으면 SYSTEM 탭 값이 들어갑니다.
  2. RUN 화면 이미지: Locate ToolBlock 안 CogFixtureTool1 의 출력 이미지. 없으면 입력 이미지를 보여 줍니다.
  3. RUN 결과 표: 판정 툴의 Input / Output 항목이 열이 됩니다 (항목 이름 = 열 제목).

스크립트 작성 요령

  1. 최상위 바로 안의 툴은 실패할 때 Error 가 아니라 Reject 를 냅니다. Error 가 나면 뒤의 툴이 실행되지 않아 이전 검사 값이 남습니다.
  2. 안쪽 ToolBlock 스크립트는 시작할 때 출력을 0 으로 두고, 툴이 실패하거나 입력 이미지가 없으면 그 자리에서 Reject 로 멈추고, 성공했을 때만 출력에 값을 넣습니다.
  3. 실패할 수 있는 툴에서 출력 바인딩(링크)을 쓰지 않습니다. 출력은 스크립트에서 직접 넣습니다.

저장

  1. VProSTD 의 SAVE 는 Minimum 으로 저장합니다. QuickBuild 에서 저장할 때도 이미지·결과를 빼고 저장하는 것을 권장합니다.

새 레시피를 받았을 때 확인 순서

  1. 출처를 아는 파일인지 확인합니다 (.vpp 는 스크립트 코드를 포함할 수 있음).
  2. Recipe Path 에 넣고 RECIPE 탭에서 LOAD → 경고 창·빨강 로그(스크립트 오류)가 없는지 봅니다.
  3. File Mode 로 OK 이미지, NG 이미지, 빈 이미지를 각각 검사해서 판정이 맞는지 봅니다.
  4. 카메라로 기준 제품을 검사합니다 → 노출 맞춤 → SAVE CAMERA (노출 저장) → File Mode 끈 상태로 SAVE.

11. 검사 시험 (File Mode)

그림 11-1: CONNECT CAMERA 탭 File Mode 부분그림 준비 중

카메라 없이 저장된 이미지로 검사합니다.

  1. CONNECT CAMERA 탭에서 File Mode 를 켭니다.
  2. Single Image (이미지 1장) 또는 Image Folder (폴더 안 이미지 전체) 를 고릅니다. 첫 이미지가 화면에 보입니다.
  3. RUN 탭에서 RUN ONCE (1장씩) 또는 AUTO RUN.
    • 폴더는 마지막 이미지까지 검사하면 AUTO RUN 이 스스로 멈춥니다 (폴더의 마지막 이미지까지 검사함).
    • 다시 AUTO RUN 을 누르면 처음부터 검사합니다.
    • 읽을 수 없는 파일은 ERROR 로 기록하고 다음 파일로 넘어갑니다.
  4. 끝나면 File Mode 를 끕니다.

카메라 모드의 AUTO RUN 은 STOP 을 누를 때까지 계속 찍어서 검사합니다. 카메라에서 이미지를 얻지 못하면 스스로 멈춥니다 (카메라에서 이미지를 얻지 못함).
